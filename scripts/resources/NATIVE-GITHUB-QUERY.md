# Real GitHub query in the original PSP update UI

This is a local v@PRODUCT_VERSION@ query-only test build. It contacts GitHub through the production authenticated HTTPS transport while retaining the PSP's original System Update screens, language and theme. It does not download or install a newer release from that screen yet. A newer compatible release produces an error and a diagnostic entry until the verified native download/installer handoff is implemented. No Sony network fallback is used.

This iteration disconnects and reconnects Wi-Fi to the same profile between eligible native pre-TLS attempts. It waits for APCTL state 0 before connecting, then state 4/IP readiness before creating a fresh DNS/socket attempt. The profile is captured from the XMB's last selected saved connection and rechecked before reconnecting; unavailable/changed profiles stop recovery. Shared libraries and drivers remain loaded. The four-extra-attempt budget, original deadline, certificate checks and cancellation remain in force. A successful connection stops retries; TLS/certificate, HTTP, metadata and unsafe-cleanup errors are not retried. LED appearance is not the acceptance signal: logs must show actual disconnection, reconnection and IP readiness. Earlier owner reports confirm native no-update and cancellation, but recovery during this new reassociation still needs PSP evidence.

1. Keep the previous package and back up the memory card. Copy the three matching folders from `PSP/GAME` to the same location on the card: `PROUPDATE`, `FastRecovery` and `PROXUPDATE`. Keep the supplied `PROXUPDATE/cacert.pem` with the matching client. Preserve existing reports, configuration and plugins.
2. With the memory card inserted, charger connected and sufficient battery, open the PRO-X Installer from Games. Press X to install, wait for Done, then press X to start PRO-X. Confirm System Information shows `6.61 PRO-X @PRODUCT_VERSION@`. This is the existing manual installer behavior.
3. Set the PSP clock correctly for certificate validation. Open Settings -> System Update -> Update via Internet, select the saved connection using the PSP's original interface and wait. For this no-update query, the charger/battery installation threshold is not required; the card, matching client and CA file are required. Equal/older product versions and draft/prerelease entries must not be offered as updates.
4. Expect the PSP's original latest-version message only after a successful authenticated query. A network, certificate, missing-file or protocol error must remain an error. Press the system's Cancel button to return to the XMB. Repeat three times without reopening Installer/Fast Recovery, then cancel during checking and run another query. DNS/TCP failures may now recover automatically within the same invocation; successful first attempts do not prove retry recovery. Record whether each run succeeded, failed or was cancelled.
5. Return `PSP/GAME/PROXUPDATE/native-report-NNN.txt` from each attempt and `PSP/GAME/PROXUPDATE/dispatch.txt`. Report the message and whether cancellation returned to XMB. No profile names, passwords or authentication tokens are logged.

The existing application updater remains available through a manual Games launch and keeps its previous flow. Do not use that path for this native-UI test. Do not start the Installer, remove the card or suspend the console while the native query worker is active. Full native offer/download/installation, automatic restart, Infinity startup and powered-on card reinsertion remain pending. This package has not been published as a release and contains no stable OTA assets.

The service stays resident between native queries. Copying a new client over the old one does not replace the already running worker: complete the manual install/start in step 2 before testing this iteration. Check that new reports contain the build ID in this package's manifest. Preserve earlier reports; do not restart CFW between the repeated queries requested in step 4.
