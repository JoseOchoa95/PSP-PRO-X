# Original System Update background lifecycle test

This v0.3.4 package is an explicit **no-flash diagnostic for the Settings flow**. It does not download or install a GitHub update. Its offer and download bar are simulated to test a background module inside the original native screen, input ownership and CFW restart using Cross on completion. This is not the separate official firmware installer's UI and is not a completed background installer. The system's own theme/language remain in control.

The manual PRO-X Installer is unchanged in behavior: installing this diagnostic CFW still writes its matching modules and uses X to install and X to start CFW. Keep the previous v0.3.3 working package and matching recovery files. Firmware must already be 6.61; no Infinity setup/change is performed.

1. Keep storage and AC connected with battery at least 50 percent. Copy the three matching folders under PSP/GAME: PROUPDATE, FastRecovery and PROXUPDATE. Keep both `native-install-preview.prx` and `native-preview-reboot.prx` in PROXUPDATE alongside EBOOT.PBP and cacert.pem. This owner-private diagnostic additionally requires `native-completion.rco` (377448 bytes, SHA-256 `714c0af3c51f61a895311ee1e58e719d8ed7fc5d3e5e441de38d67133617c265`), supplied separately as read-only original resource data; it is deliberately absent from this binary/source ZIP. Copy it into PROXUPDATE. Missing or changed resource data stops the test. Preserve configuration, plugins, games and reports.
2. Run PROUPDATE from Games, press X to install and X to start PRO-X. Check System Information for `6.61 PRO-X 0.3.4`; wait ten seconds in inactive XMB.
3. Enter Settings -> System Update -> Update via Internet. The original network selection may still connect, but this diagnostic makes no GitHub request. The native offer is simulated and must not be interpreted as an available release.
   Missing AC or insufficient battery must now stop the accepted offer before the simulated bar advances or the background module starts. The offer/query still does not require installation power; readiness is checked again at handoff.
4. Accept the offer once. At about 96 percent the no-flash background module runs for eight seconds inside the original native download screen. The bar should then finish and the stock XMB completion page should show the original standalone updater's localized first sentence (English: “Update completed.”). It must remain there without an automatic restart timer. The native Back icon/label should be absent; Cross (X) is the only completion action. Release Cross, then press it again to request the matching PRO CFW restart. Circle is ignored on completion and must neither restart nor return to XMB. No console or new installation-consent question is added. Sony's installer must never launch. This is a simulated completion/lifecycle test, not an actual completed update or reuse of the standalone installer's page layout.
5. Cancel an earlier run before the final section and verify return to XMB; its native Circle/Back navigation must remain available there. During the eight-second background section, Circle should still be blocked. Once completion appears, wait longer than 25 seconds (preferably two minutes), press Circle and confirm no restart/return occurs, then use Cross. Holding offer acceptance across the transition must not restart; a release and new Cross press are required. The five-second native-text-lookup limit is a startup failure watchdog, not a delay before restarting. While the completion page waits for input, the live probe renews ownership; a dead/failed probe loses that renewal within 25 seconds and reports failure instead of rebooting automatically. Do not assume a successful reboot when an error is reported.
6. After restart, check the product label and SELECT menu. No update was installed by this preview. Repeat with a changed system language/theme if possible. Copy `PROXUPDATE/install-preview-*.txt`, `native-report-*.txt`, `native-download-*.txt` and `dispatch.txt` for analysis. The text reports are files only, never a visible console.

Native background module loading, Back visibility, rendering/input continuity, cancellation and Cross-only restart on this new identity require owner PSP testing. The owner reports that the preceding resource-backed completion preview worked; that does not validate the new navigation changes. Production verified staging/flash/storage commit, removal of installer confirmations and background OTA activation are still pending; stable catalog/TLS/versions/contracts remain unchanged in the non-diagnostic build. The standard distribution packager rejects this preview and no compact OTA manifest is generated for it. Do not publish this diagnostic as a stable update.
