# Original PSP download progress — virtual, incomplete diagnostic

This v@PRODUCT_VERSION@ package tests the original PSP download progress screen and cancellation. It is not a real update. After a successful authenticated no-newer-release query it simulates a 1 MiB offer. Accepting creates only a virtual file descriptor, returns paced zero-filled test blocks and accounts for the original UI's writes without creating any EBOOT.PBP or update directory. The native transfer is forced to fail with at least 32 KiB still missing, before completion can launch anything. No package download, verified stage, flash write, installation or restart is enabled. Private diagnostic logs still write to PROXUPDATE.

This iteration fixes the error response at the intentional cutoff: filesystem failures, incomplete EOF and invalid read sizes are mapped into the original downloader's recognized error domain. The earlier build showed 96 percent and allowed cancellation back to XMB, but did not establish the intended automatic error transition. The new test must verify that transition as well as cancellation while the bar is still moving.

The virtual writer recognizes only the original UPDATE or _UPDATE temporary EBOOT paths, including the inspected twenty-digit temporary suffix, on stock ms0/ef0/eh0 devices. Mutating metadata calls are simulated without calling filesystem APIs. Real read-only media queries remain available; unknown write paths, flags, commands, stale descriptors, wrong worker threads and invalid byte counts are rejected. Synthetic copies are bounded, cancellation is checked while pacing each chunk, and no wait or caller-buffer copy occurs under the brief state lock. The original UI/resources handle navigation and progress; there is no custom renderer.

1. Preserve the accepted native-github-query package and earlier reports. Copy the matching PROUPDATE, FastRecovery and PROXUPDATE folders from this package, including cacert.pem. Back up the card and retain settings/plugins.
2. With SD inserted, charger connected and adequate battery, open PROUPDATE (the Installer) from Games: X installs, wait for Done, then X starts PRO-X. Do not use the Games entry named PRO-X v@PRODUCT_VERSION@ System Update for the native test. This step replaces the resident VSH provider/virtual writer.
3. Use Settings -> System Update -> Update via Internet. After real checking completes, accept the simulated offer. Expect the PSP's original download screen and increasing progress for roughly eight seconds. First cancel while it is around 20–50 percent, before the 96-percent cutoff; confirm the original cancel prompt if shown and verify return to XMB.
4. Repeat, accept and let progress run without cancelling at 96 percent. It must stop before 100 percent and show a controlled native download error automatically, because the last chunk is deliberately unavailable. If it stays on progress for more than ten seconds after the cutoff, record that failure and cancel to exit. It must not say installation completed, launch an updater or create/replace an UPDATE EBOOT. Acknowledge/cancel the error back to XMB. Stop if any unexpected installation starts.
5. Query again to confirm reuse after cancellation/error. Return native-report-NNN.txt and dispatch.txt, and describe whether the bar/percentage moved, what happened when cancelling and how the forced error exited. A photo/video of the moving original progress screen is useful if convenient. System language/theme changes should continue to use installed resources, but no new translation strings are added.

The stock temporary name _UPDATE is intentionally recognized by the virtual writer; no corresponding real file is created. If the original screen refuses before progress or a different call/thread/path is encountered, it must fail closed and the reports will guide the next integration. This diagnostic does not claim that real package progress, native prerequisite/release-note presentation, single-consent PRO-X installation, original standalone installer UI reuse or automatic restart works. The independently tested verified download/staging backend remains disconnected.

After testing, restore the previously accepted pro-x-@PRODUCT_VERSION@-661-native-github-query package and run that PROUPDATE Installer X/Done/X once. Its seven-query/reconnect hardware acceptance belongs to build pro-x-2a88108fd7d4. Overwriting client files alone does not replace resident VSH or remove the diagnostic provider. Do not publish this preview or use it as a stable OTA asset.
